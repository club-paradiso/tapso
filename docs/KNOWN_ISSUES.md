# Known issues

- `RESOLVED` 2026-09-12: the transit API is verified in production at `https://tapso-api.vercel.app` (build `b59e9e60b863`) — HTTP, canonical credential, and live TAGO reads all observed. See `PRODUCTION_TRANSIT_API.md` → *Production verification*. Automatic matching stays withheld; that is the freshness gate, not a deployment problem.
- Reading `503 BLOCKED_BY_CREDENTIALS` from a deployment: `/health` names the cause. `credential.source: "missing"` with `deprecatedNamePresent: false` means no key reached the running build — either none is set for that environment, or that deployment did not pick it up. Do not assume which: on 2026-09-12 a Production variable added after the fact did reach the already-running build `b59e9e60b863`. `/health` describes the running build and is the authority; redeploy production if it disagrees with the dashboard. `deprecatedNamePresent: true` means the retired `PUBLIC_DATA_SERVICE_KEY` was set instead; Vercel cannot store a `PUBLIC_` name as a Sensitive secret, so the deployment ignores it by design.
- `BLOCKED_BY_CREDENTIALS`: APNs remote Live Activity updates need an Apple developer team, bundle identifiers, signing key, and device token flow.
- Local credential precedence is not identical across tools. The Node tools resolve through `process.env`, where a value exported in the shell beats `.env.local`, because Node's `--env-file` does not overwrite a variable that is already set (verified on Node v22.22.2). `scripts/tago/probe.py` reads `.env.local` itself and lets the file win. The documented `env -u TAGO_SERVICE_KEY node --env-file=.env.local …` wrapper collapses the difference by clearing the exported copy first; keep the wrapper, or keep only one copy of the key.
- Node's `--env-file` does not inspect file permissions. `scripts/tago/probe.py` refuses a `.env.local` that is not `0600`; `scripts/ride-capture/capture.ts` only warns, because refusing mid-boarding would cost a real ride.
- `UNVERIFIED`: the mobile Ride Capture Controller has never run on a real iPhone. Its capture logic is covered by deterministic tests and the operator endpoints were exercised over HTTP against a synthetic upstream, but IndexedDB, the screen wake lock, the lifecycle listeners and the export sheet are browser wrappers that no test here touches. See `RIDE_CAPTURE_CONTROLLER.md`.
- iOS Safari suspends a backgrounded tab, and a suspended tab stops polling. The controller records `hidden`/`visible` events and the report attributes the resulting hole to the instrument rather than to TAGO, but nothing can keep collection running with the screen locked. Keep the screen on and the page in front for the length of a capture.
- `NO_SOURCE_TIMESTAMP`: TAGO live locations carry no provider observation timestamp. Automatic passenger matching stays withheld and every freshness-dependent path fails closed until a controlled ride defines a rule. This is a product gate, not a bug.
- `STALE_SCRIPT`: `scripts/transit-spike/resolve-route.ts` imports `services/api/src/publicDataProvider.ts`, which the TAGO migration removed. The script cannot load and is kept only as migration history.
- `services/api/test` predates the TypeScript configuration added with the production API and does not satisfy `noUncheckedIndexedAccess`, so `services/api/tsconfig.json` typechecks `api`, `src`, and `scripts` only.
- `BLOCKED_BY_PAID_MEMBERSHIP`: no paid Apple Developer Program team is reachable from this machine. - `UNVERIFIED`: physical-device Lock Screen, Dynamic Island, haptic, battery, and accessibility behavior. No physical device is registered to any available team.
- Backend matching mirrors core policy but is not generated from a shared cross-language specification; drift tests are needed.
- The app currently exposes the deterministic demo, not full stop/route search or vehicle-confirmation screens.
- Demo haptics occur only while the app is executing; no unsupported background haptic guarantee is made.
- Ride sessions default to one process's memory and are disabled whenever `VERCEL` is set, answering `503 SESSIONS_UNAVAILABLE`. A deployment that sets `TRANSIT_SESSION_STORE=redis` with Upstash credentials gets a durable store and may enable them. This is a separate concern from automatic matching, which is withheld by the open field-validation gate rather than by the store; see `exec-plans/TASK_C_SOURCE_FRESHNESS.md`.
- The Upstash session store has been verified against the live service (store 15/15, preview deployment 12/12, 2026-09-23; see `exec-plans/DURABLE_JOURNEY_SESSIONS.md` milestone 6), but production has not been switched to it: production still runs the memory store with sessions disabled on Vercel. Moving production is a separate decision that needs `TRANSIT_SESSION_KEY_PREFIX=tapso:prod:journey-session:` and does not by itself enable automatic matching.
- Journey sessions read TAGO uncached, by design: server-observed cadence is only evidence when consecutive reads are genuinely consecutive, and the shared 20-second snapshot cache would replay one receipt as several. The cost is that each active session polls upstream directly, so TAGO quota consumption scales with concurrent riders rather than with routes. Sessions are off by default on serverless, so this is not live today; it needs a shared collector or a session-scoped cache before broad rollout.
- Field-validation submission (`POST /capture/:id/submit`) stays operator-only. Friends use the separate beta flow (`/ride-capture/beta.html`, invite links, scoped tester credentials, server-enforced ride ownership); `RIDE_CAPTURE_OPERATOR_TOKEN` is never handed out. Beta rides count only toward the versioned `beta-matcher-30-boardings-v2` matcher campaign, never toward v1, and never toward provider/cadence calibration. See `exec-plans/BETA_FIELD_TESTER.md`.
- `UNVERIFIED`: the beta tester page has been exercised in a 390 px Chromium viewport with a mocked network, not yet on a real iPhone. Beta testing is off unless `BETA_TESTERS_ENABLED=true` on the Railway collector. Beta rides survive a collector restart through a fenced Upstash capture journal (deterministic two-process restart tests); the journal's Lua script has not yet run against live Upstash, and snapshots during the downtime are missing, not invented. Operator rides remain process-memory: a restart still loses an in-progress operator ride.
- Submissions are stored in Upstash Redis with no TTL. They are safe only if eviction is disabled for that database, and this repository cannot check that setting. It must be confirmed in the Upstash console.
- Ride captures taken before 2026-09-22 carry no `matchGate` section, because the matcher replay did not exist. They can still be re-analysed, but only from the raw capture: `analyzeRideCapture` recomputes the report from the stored snapshots, and `scripts/ride-capture/batch-analyze.ts` does that for a whole folder. A saved `*.report.json` alone cannot be re-analysed, because it keeps no per-snapshot candidates, coordinates or direction codes. The phone controller keeps one working raw capture in IndexedDB, replaces it when the next ride starts, and offers it for download only on the finish screen. The Railway collector keeps a finished session in memory for two hours and exports its raw capture only through the operator-authenticated `GET /capture/:sessionId/raw`, which the background finish screen calls. So a ride whose raw was not saved inside that window cannot be recovered. A capture whose `matchGate.usableForGate` is `false` does not count toward the thirty boardings.
- Automatic vehicle selection is off on every deployment (`TRANSIT_AUTOMATIC_MATCHING_ENABLED=false`). Journey sessions run in shadow mode: candidates are ranked and cadence evidence is published, but only an explicit rider confirmation selects a vehicle. Zero of the 30 boardings the acceptance gate requires have been observed.
- Per-caller rate limiting is a per-warm-instance fixed window, not a global limit. A shared counter would need a shared store.
- Local workspace folders managed by iCloud/FileProvider can introduce extended attributes or offloaded files that interfere with simulator signing; keep sources downloaded and use DerivedData outside the synced tree.
