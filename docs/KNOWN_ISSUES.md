- Reading `503 BLOCKED_BY_CREDENTIALS` from a deployment: `/health` names the cause. `credential.source: "missing"` with `deprecatedNamePresent: false` means no key reached the running build — either none is set for that environment, or that deployment did not pick it up. Do not assume which: on 2026-09-12 a Production variable added after the fact appeared to reach the already-running build `b59e9e60b863` (`INFERRED` from an unchanged `build.commit`; no recorded observation identifies the deployment that answered). `/health` describes the running build and is the authority; redeploy production if it disagrees with the dashboard. `deprecatedNamePresent: true` means the retired `PUBLIC_DATA_SERVICE_KEY` was set instead; Vercel cannot store a `PUBLIC_` name as a Sensitive secret, so the deployment ignores it by design.
- `BLOCKED_BY_CREDENTIALS`: APNs remote Live Activity updates need an Apple developer team, bundle identifiers, signing key, and device token flow.
- Local credential precedence is not identical across tools. The Node tools resolve through `process.env`, where a value exported in the shell beats `.env.local`, because Node's `--env-file` does not overwrite a variable that is already set (verified on Node v22.22.2). `scripts/tago/probe.py` reads `.env.local` itself and lets the file win. The documented `env -u TAGO_SERVICE_KEY node --env-file=.env.local …` wrapper collapses the difference by clearing the exported copy first; keep the wrapper, or keep only one copy of the key.
- Node's `--env-file` does not inspect file permissions. `scripts/tago/probe.py` refuses a `.env.local` that is not `0600`; `scripts/ride-capture/capture.ts` only warns, because refusing mid-boarding would cost a real ride.

- `RESOLVED` 2026-09-29: this line said backend matching mirrors the core policy and needed drift tests. - Ride sessions default to one process's memory and are disabled whenever `VERCEL` is set, answering `503 SESSIONS_UNAVAILABLE`. A deployment that sets `TRANSIT_SESSION_STORE=redis` with Upstash credentials gets a durable store and may enable them. - The Upstash session store has been verified against the live service (store 15/15, preview deployment 12/12, 2026-09-23; see `exec-plans/DURABLE_JOURNEY_SESSIONS.md` milestone 6), but production has not been switched to it: as last recorded (2026-09-23), production still runs the memory store with sessions disabled on Vercel. Moving production is a separate decision that needs `TRANSIT_SESSION_KEY_PREFIX=tapso:prod:journey-session:` and does not by itself enable automatic matching.
- Journey sessions read TAGO uncached, by design: server-observed cadence is only evidence when consecutive reads are genuinely consecutive, and the shared 20-second snapshot cache would replay one receipt as several. The cost is that each active session polls upstream directly, so TAGO quota consumption scales with concurrent riders rather than with routes. Sessions are off by default on serverless, so this is not live today; it needs a shared collector or a session-scoped cache before broad rollout.

- Ride captures taken before 2026-09-22 carry no `matchGate` section, because the matcher replay did not exist.
