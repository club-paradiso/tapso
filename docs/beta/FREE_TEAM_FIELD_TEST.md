# 무료 계정 현장 테스트 가이드

유료 Apple 개발자 등록 **전에**, 무료 계정(Personal Team)으로 확인할 수 있는 것을 모두 확인하기 위한 안내입니다.
소유자가 직접 따라 하는 문서라 한국어로 씁니다. 케이스 번호(B-1, R-1 …)는 `docs/DEVICE_TEST_PLAN.md` §"Beta field protocol"과
같습니다. 결과는 `docs/beta/RELEASE_DECISION.md`로 이어집니다.

## 1. 이 테스트로 확인되는 것과 안 되는 것

| 확인할 수 있음 | 확인할 수 없음 (유료 등록 후) |
|---|---|
| 버스 확인부터 하차까지 앱 화면 전체 | 앱을 **완전히 닫은** 상태에서 잠금화면 갱신과 하차 알림 (APNs 푸시 필요: B-7, B-8) |
| 앱을 켜 둔 상태의 잠금화면과 다이내믹 아일랜드 | TestFlight 배포, 다른 사람 기기에 설치 |
| "앱을 나가도 계속 알려 주기"를 켠 상태의 잠금화면 갱신 | |
| 기다리는 중, 두 정거장 전, 다음 정거장, 도착, 지나침, 위치 지연·끊김 화면 | |
| 4개 언어, VoiceOver, 큰 글씨, 모션 줄이기, 저전력 모드 | |
| 의견 보내기와 접수 번호 | |

**앱을 위로 밀어 완전히 닫으면 잠금화면이 멈추는 것은 지금 정상입니다.** 푸시가 없어서 그렇고, 버그로 보지 않습니다.
실제 탑승 테스트에서는 앱을 켜 두거나 "앱을 나가도 계속 알려 주기"를 켜 주세요.

## 2. 준비물

- Xcode가 설치된 Mac. CI는 Xcode 16.4로 빌드합니다.
- iOS 17 이상 아이폰. 다이내믹 아일랜드가 있는 기종이 좋고, 없는 기종이 하나 더 있으면 B-2까지 확인할 수 있습니다.
- USB 케이블, Apple ID.
- 이 저장소의 최신 `main`.

## 3. 설치 (처음 한 번)

1. Mac에서 `git pull` 후 `apps/ios/Tapso.xcodeproj`를 엽니다.
2. Xcode › Settings › Accounts에서 Apple ID로 로그인합니다. 팀 목록에 "(Personal Team)"이 보이면 됩니다.
3. 프로젝트의 세 타깃(Tapso, TapsoLiveActivity, TapsoShare) › Signing & Capabilities에서 Team이 본인 Personal Team인지
   확인합니다. 저장소에는 `89CGFQ24U5`가 들어 있습니다. 다른 Apple ID라면 세 타깃 모두 본인 팀으로 바꿔 주세요.
   번들 ID를 쓸 수 없다는 오류가 나오면 그 화면을 저에게 알려 주세요. 임의로 바꾸지 마세요(App Group도 같이 바뀝니다).
4. 아이폰: 설정 › 개인정보 보호 및 보안 › 개발자 모드를 켭니다(재시동 필요).
5. 아이폰을 Mac에 연결하고, Xcode 위쪽에서 스킴을 **Tapso Beta**로, 대상 기기를 본인 아이폰으로 고른 뒤 Run(⌘R)을 누릅니다.
6. 처음 실행할 때 "신뢰하지 않는 개발자"가 나오면: 설정 › 일반 › VPN 및 기기 관리에서 본인 Apple ID를 신뢰합니다.
7. **설치 확인:** 홈 또는 여정 메뉴의 "의견 보내기 (베타)"를 엽니다. 맨 아래 작은 글씨의 빌드 정보가 `TAPSO 0.1.0 · Build 1 · <커밋> · BETA`처럼
   **BETA**로 끝나야 합니다. DEBUG라면 스킴을 잘못 고른 것입니다.

**7일 규칙:** 무료 계정으로 설치한 앱은 7일 뒤 열리지 않습니다. 테스트하는 날 아침에 Xcode에서 Run을 한 번 더 누르면 됩니다.

### 스킴 두 가지

| 스킴 | 구성 | 언제 |
|---|---|---|
| **Tapso Beta** | Beta: 실제 제주 데이터, 여정 기록, "방금 정류장을 지났어요", 의견 보내기 | 실제 탑승 테스트. 결과는 이것만 인정 |
| Tapso | Debug: 위 기능에 더해 "샘플 여정으로 둘러보기" | 집에서 화면 흐름 연습. 결과로 인정하지 않음 |

## 4. 테스트하는 날마다

- 앱을 다시 설치(7일 규칙)하고 빌드 정보가 BETA인지 봅니다.
- 기록해 둘 것: 기종, iOS 버전, 다크·라이트 모드, 글자 크기, 모션 줄이기, 저전력 모드, Wi-Fi·셀룰러.
- 화면 기록: 제어 센터에 화면 기록을 추가해 두면 잠금화면과 아일랜드를 그대로 남길 수 있습니다.
- 배터리를 충분히 충전하세요. "앱을 나가도 계속 알려 주기"는 배터리를 더 씁니다.
- 안전: 버스 안에서는 앉거나 손잡이를 잡은 뒤에 조작하세요.

## 5. 테스트 목록

모든 케이스는 **아직 안 함**에서 시작합니다. 실제 아이폰에서 직접 본 것만 통과입니다.

### 기기와 화면 (B)

| ID | 할 일 | 통과 조건 |
|---|---|---|
| B-1 | 다이내믹 아일랜드 기종으로 한 번 탑승: 기다림 → 탑승 → 두 정거장 전 → 다음 정거장 → 도착. 음악을 틀어 최소 표시도 봅니다 | 아일랜드(작게, 최소, 길게 눌러 펼침)가 매 순간 앱과 같은 말을 함. 기다리는 동안 "N정거장 전"이 보이고, 버스부터 목적지까지의 숫자는 안 보임 |
| B-2 | 다이내믹 아일랜드 없는 기종, 잠금화면만 | B-1과 같은 흐름이 잠금화면에서 보임 |
| B-3 | 설정 › 손쉬운 사용 › 더 큰 텍스트를 최대로 | 앱의 큰 숫자, 정류장 이름, 버튼이 잘리지 않음. 잠금화면이 잘리면 사진으로 기록 |
| B-4 | VoiceOver를 켜고 한 번 탑승 | 상태 → 숫자 → 목적지 → 할 일 순으로 읽음. 기다리는 중에는 "탈 정류장에서 N정거장 전" |
| B-5 | 모션 줄이기 켬 | 움직임 없이도 상태를 알 수 있음 |
| B-6 | 앱을 켠 채 10분 → 다른 앱 10분 → 화면 잠금 10분. "앱을 나가도 계속 알려 주기"를 끄고 한 번, 켜고 한 번 | 앱이 켜져 있으면 잠금화면 갱신. 켜기를 켰으면 다른 앱이나 잠금 중에도 갱신. 2분 넘게 갱신이 없으면 "늦게 들어와요" 표시 |
| B-9 | 설정 › 탑서 › 실시간 현황을 끄고 여정 시작 | 여정 화면이 꺼져 있다는 사실과 켜는 방법을 알려 줌 |
| B-10 | 여정 중 아이폰 재시동 | 앱을 열면 "여정을 이어가요"로 돌아오고, 오래된 정보를 새것처럼 보이지 않음 |
| B-11 | 설정 › 탑서 › 언어를 English, 简体中文, 日本語로 바꿔 각각 한 번 탑승 | 앱, 잠금화면, 아일랜드, 알림이 그 언어. 정류장 이름은 한국어 그대로 |
| B-12 | 저전력 모드에서 B-6 반복 | B-6과 같은 결과. 다르면 기록 |

### 실제 탑승 (R)

| ID | 탑승 | 확인할 것 |
|---|---|---|
| R-1 | 1–3정거장 짧은 구간. 버스가 아직 1–2정거장 전일 때 "이 버스 확인하기" | 타기 전에는 기다림으로 보이고, 타기 전에 "준비하세요" 알림이 오지 않음. 탄 뒤 알림은 제때 |
| R-2 | 4–10정거장, 배차가 잦은 시내버스 | 한 정거장마다 숫자가 줄고, 두 정거장 전·다음 정거장·도착이 서로 다른 화면 |
| R-3 | 10정거장 넘는 구간 (급행·간선) | 진행 막대가 자연스럽고 알림이 제때 |
| R-4 | 같은 번호에 방향이 여러 개인 노선 | 타기 전에 방향을 구분할 수 있음 |
| R-5 | 같은 노선 버스 두 대가 다가올 때 | 번호판으로 구분 가능. 앱이 혼자 다른 버스로 바꾸지 않음 |
| R-6 | 공공 데이터가 늦거나 버스가 잠시 사라질 때 (생기면 기록) | 상황에 맞는 문구, 숫자에 "마지막 확인" 표시 |
| R-7 | 여정 중 앱을 다시 열기 | 오래된 정보를 새것처럼 보이지 않고 이어짐 |
| R-8 | 화면을 잠근 채 도착 | 도착 알림 한 번. "내렸어요"로 끝남 |
| R-9 | 일부러 다른 버스를 확인 | 앱이 몰래 버스를 바꾸지 않음. "다른 버스예요"와 의견 "다른 버스가 선택됐어요"가 작동 |
| R-10 | 일부러 내릴 정류장을 지나침 | "안내 마치기"와 돌아가는 방법이 나옴. 내렸다고 단정하지 않음 |

> 자동 버스 매칭과 하이브리드 위치 추적은 서버 스위치로 꺼져 있습니다. 이번 테스트 범위가 아닙니다.

## 6. 기록과 보고

**가장 쉬운 방법:** 케이스마다 채팅으로 저에게 알려 주세요. 형식은 아래처럼 짧아도 됩니다.

```
R-2 · 2026-10-21 08:10 · 365번 제주버스터미널 → 제주시청
기대: 두 정거장 전에 알림 / 실제: 한 정거장 전에 옴
화면 기록 있음 · 접수 번호 A1B2C3
```

받은 내용은 제가 번호판 일부와 얼굴, 전화번호 같은 정보를 지우고 `artifacts/device-validation/`에 증거 파일로 정리합니다.
직접 쓰고 싶으면 그 폴더의 `TEMPLATE.md`를 복사해 쓰면 됩니다.

**문제가 생기면:** 그 자리에서 여정 메뉴 › "의견 보내기 (베타)"로 보내 주세요.
- 종류를 고르고, 무엇이 달랐는지 한 줄 적고, "여정 기록 함께 보내기"를 켜면 원인을 찾기 쉽습니다.
- 위치 기록, 연락처, 사진은 보내지 않습니다.
- "보냈어요 · 접수 번호"가 나오면 서버에 저장된 것입니다. 그 번호를 저에게 알려 주세요.
- "보내지 못했어요"가 나오면 "내용 공유하기"로 메모나 메시지에 저장해 두세요.

정류장을 지났는데 앱이 반응하지 않으면 여정 메뉴 › "방금 정류장을 지났어요"를 눌러 두세요. 여정 기록에 실제 통과 시각이 남습니다.

**접수된 의견 보기 (소유자):** 운영자 토큰이 필요합니다. 토큰은 채팅이나 GitHub에 붙여넣지 마세요.

```bash
curl -s -H "Authorization: Bearer $RIDE_CAPTURE_OPERATOR_TOKEN" \
  "https://tapso-api.vercel.app/operator/feedback?limit=50"
```

의견은 30일 동안 보관됩니다.

## 7. 유료 등록으로 넘어가는 기준

아래가 모두 맞으면 유료 등록(`docs/beta/HUMAN_ACTION_REQUIRED.md` 3번부터)으로 넘어갑니다.

1. 위 표의 B와 R 케이스가 모두 통과했거나, 남은 문제가 무엇이고 왜 괜찮은지 적혀 있다.
2. 남은 문제 중 "버스를 잘못 따라감", "알림이 틀린 때 옴", "숫자가 틀림"처럼 승객을 잘못 내리게 할 수 있는 것은 하나도 없다.
3. R-1, R-2는 서로 다른 날 두 번 이상 통과했다.

유료 등록 뒤에는 푸시를 연결하고 B-7, B-8만 추가로 확인하면 됩니다.
