## Limits

The overnight capture verifies authentication, discovery, real stop data and successful empty location responses. The separate daytime follow-up verifies actual vehicle numbers, coordinates, `nodeord`, `nodenm`, and `nodeid`. The API itself does not establish why the overnight result was empty.

TAGO's location schema has no documented source observation timestamp. The adapter keeps receipt time separate and automatic matching/progress remain withheld when source freshness is unavailable. Passenger readiness, cadence and direction semantics need their own evidence.

The longer bounded cadence probe remains documented separately. This report records only the independently repeated credential, discovery, and daytime field checks.

## Credential handling

The source `.env.local` is Git-ignored, mode 0600, and contains the key only under `PUBLIC_DATA_SERVICE_KEY`. This work used only that registered value; no previous key was tested or copied. The isolated worktree references the same private env file instead of duplicating the credential. The portal's key issuance/revocation history could not be rechecked because the available browser session is logged out; local registration and API acceptance do not by themselves prove server-side revocation of the earlier key.

No credential, authenticated URL, or raw vehicle inventory is included in Git. Full allowed-field responses remain in ignored local `work/`. The tracked report contains only IDs, public route endpoints and counts.

## Reproduction

From the feature checkout, with `.env.local` present:

```bash
mkdir -p work
python3 scripts/tago/probe.py > work/tago-probe.json
python3 -m unittest discover -s scripts/tago -p 'test_*.py'
npm --prefix services/api test
```

The Python probe's local env file takes priority over inherited shell credentials. To run the server, clear any inherited key first:

```bash
env -u PUBLIC_DATA_SERVICE_KEY node --env-file=.env.local --experimental-strip-types services/api/src/server.ts
```
